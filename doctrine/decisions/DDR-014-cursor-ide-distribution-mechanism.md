# DDR-014: Cursor IDE Distribution Mechanism

**Status:** Accepted  
**Date:** 2026-03-03  
**Author:** Curator Claire  
**Related:** DDR-008 (Framework Distribution), DDR-013 (Doctrine-Enabled Team Tooling)

---

## Context

The doctrine framework distributes agent configuration to multiple IDE platforms (`.github/` for Copilot, `.claude/` for Claude, `.opencode/` for OpenCode). Cursor IDE support was added in 2026-03 but lacked a distribution mechanism — consuming repositories had no automated way to receive Cursor hooks, skills, and configuration.

Key constraints:
1. Consuming repos access doctrine via **symlink** (`doctrine/ → ../regnology-agent-doctrine/doctrine`), not git subtree
2. Cursor reads from `.cursor/` at the repository root — the directory must exist there
3. Hooks are governance artifacts (should stay in sync); skills are generated; rules are project-specific
4. The distribution must work on Linux (primary), macOS, and degrade gracefully on Windows

## Decision

**We distribute Cursor configuration via a canonical source directory (`doctrine/cursor/`) and a setup script that prefers symlinks over copies.**

### Architecture

```
doctrine/cursor/              ← Canonical source (travels with doctrine symlink)
├── hooks.json                ← Hook event configuration
├── hooks/                    ← 5 validation and advisory scripts
├── setup.sh                  ← Convenience wrapper
└── README.md

.cursor/                      ← Cursor reads from here (repo root)
├── hooks.json → symlink      ← Governance: stays in sync
├── hooks/     → symlink      ← Governance: stays in sync
├── skills/                   ← Generated by deploy-cursor-skills.js
└── rules/                    ← Project-specific (not distributed)
```

### Distribution Channels

| Channel | Mechanism |
|---------|-----------|
| Symlinked doctrine | `doctrine/cursor/setup.sh` creates symlinks from `.cursor/` to `doctrine/cursor/` |
| Release artifact | `.cursor/` included in zip via `distribution-config.yaml`; `framework_install.sh` calls `setup-cursor.sh` post-install |

### Component Strategies

| Component | Strategy | Rationale |
|-----------|----------|-----------|
| `hooks.json` + `hooks/` | Symlink | Governance artifacts — must stay in sync with upstream |
| `skills/` | Generated | Derived from doctrine sources — `deploy-cursor-skills.js` creates from approaches + tactics + shorthands |
| `rules/` | Project-specific | Each repo defines its own editing rules; created empty by setup script |

## Rationale

- **Symlinks over copies** prevent drift between upstream doctrine and consuming repos
- **Canonical source in `doctrine/cursor/`** ensures the config travels with the doctrine symlink — no separate distribution needed
- **Generated skills** avoid content duplication — the deploy script reads from authoritative doctrine sources
- **POSIX-compatible hooks** (sed-based JSON extraction) work on both Linux and macOS without GNU grep dependency

## Consequences

### Positive
- Single command (`doctrine/cursor/setup.sh`) bootstraps Cursor in any indoctrinated repository
- Hook updates propagate automatically through symlinks
- Consistent skill catalog across all consuming repos (generated from same doctrine source)
- Session startup checks for unpulled doctrine updates

### Negative
- Symlinks require OS support (Windows needs developer mode or admin)
- Skills must be regenerated after doctrine changes (not automatic)
- Consuming repos need Node.js for skill generation (degrades gracefully if unavailable)

### Risks
- If `doctrine/cursor/hooks/` structure changes, all consuming repo symlinks follow immediately (no staged rollout)

## Alternatives Considered

1. **Git subtree for `.cursor/`** — Rejected: consuming repos already use symlinks for doctrine; adding a subtree for one directory adds complexity
2. **Copy-only distribution** — Rejected: copies drift; the prior session proved dual-copy issues in the source repo itself
3. **Skills inside `doctrine/cursor/`** — Rejected: skills are generated from multiple doctrine sources; including pre-built skills would create a second source of truth
